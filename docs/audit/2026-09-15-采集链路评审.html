它读得准，只是读得少

同一个模型被建成两条记录

网页解析拿到 GLM-5.3，截图识别吐出 glm-5.3，系统按精确字符串匹配，当成两个不同模型。前台并排显示两行一模一样的价格，模型总数也虚高。

已改为忽略大小写匹配，堵住来源。视觉识别刚打通凭据，不堵住会成倍放大。

后台勾了「视觉 OCR」，视觉侧仍报未配置

配置存在一个地方，读在另一个地方

后台的 Key 存进一个文件，视觉采集器去另一个文件找，两边互不相通。界面显示配好了，实际一直静默跳过。

打通后视觉识别首次端到端跑通：124 秒采到 4 条价格并入库。

手动点运行，14 毫秒返回

手动运行被降频策略静默拦下

视觉识别每 5 轮才真跑一次以省 token，但人手动点击时同样被拦，还报成「未解析出价格数据」。

降频是给定时任务的策略；人明确点了运行就该跑。

HTTP 200 + 网页 HTML，而非 API 响应

AI 修复调用打到了网站首页

Key 的地址没带 /v1，请求发到了错误路径。网关对未知路径返回 200 加一张网页，于是状态码检查放行、解析 JSON 才失败，报错只有一句 JSONDecodeError，完全指不到根因。

两类 AI 修复走同一个调用，所以一起失效。

显示「浏览器渲染 → 网页源码」，实际走截图识别
